# ADR 0006：评测案例与运行时数据隔离

- 状态：Accepted（Issue #7 的实现边界，待 PR 人工评审）
- 日期：2026-11-05
- 关联：Issue #7、Proposal #1、ADR 0002、ADR 0003

## 背景

评测案例需要同时描述诊断可见上下文与评测专用真值。若 Agent 可以读取预期根因、故障注入状态或评分标准，指标没有评测意义。Issue #3 已在运行数据库的 `diagnosis_cases` 表定义这些评测字段，但表尚无使用方。

## 决策

- 新增 `test/evaluation/cases/` 作为评测真值源目录。它不由 Go `embed` 嵌入，不被 API/Worker 镜像复制；通用 `test/fixtures/` 只放运行时可见、已脱敏的跨服务输入。
- 使用严格 JSON 契约与标准库 Go 校验器；未知字段、额外 JSON 文档、非法枚举、空候选/证据、倒置窗口、缺少恢复/清理步骤与重复 `case_id@version` 均失败。
- 新增迁移从运行数据库 `diagnosis_cases` 移除注入状态、答案、候选、证据义务、反证、健康基线和场景元数据列。若旧环境已有案例行，迁移拒绝运行并要求先人工导出/审查，绝不静默丢弃答案。表只保留运行时安全的 case key/version、分类、标题和 active 字段。
- 读取评测文件的 helper 采用默认拒绝；只有 Evaluator principal 可读取。Runtime 拒绝路径通过调用方提供的审计 sink 记录；审计 sink 缺失时拒绝访问。principal 参数本身不是身份认证，不能视为跨进程安全机制。实际隔离来自测试专用目录不嵌入、不复制进 API/Worker 镜像，且当前生产代码没有调用此 helper。生产 Prompt 使用单独的 allowlist `RuntimeContext`，没有案例 ID 或答案字段。
- 案例版本通过新文件追加；校验器拒绝同一目录中重复的 case ID 和版本，不实现覆盖/更新接口。

## 明确不做

- 不实现故障注入运行器、评测调度器、评分执行器、模型输入器或全部故障案例。
- 不将测试真值复制进生产数据库或容器镜像；不把当前案例描述为已运行的评测结果。
- 不为未存在的 Agent 运行时构造虚假调用接口。

## 安全与回滚

该变更风险为 standard：涉及评测数据完整性和结论可信度，但不扩大外部访问权限。迁移对含有任何旧 `diagnosis_cases` 行的库失败关闭，先要求维护者导出案例到受保护目录并人工确认；无行或清理后的库可前滚。回滚会重建空的答案列，已通过新契约保存的案例文件不受影响。

当前 API/Worker 没有评测文件读取调用，容器构建仅复制最终二进制。未来评测运行器必须继续使用独立进程/权限和受控工件，不得把 `test/evaluation` 接进 API 镜像或 Prompt。评测真值在公开仓库中，按公开数据处理；此隔离目标是防止运行时答案泄漏，不是保密评测答案。
